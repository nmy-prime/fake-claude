## 一、做了什么

`ToolService.shellCommand()` 之前是假的：只打印一句"执行命令：xxx"，然后返回字符串 `"执行成功"`，模型永远拿不到真实输出。今天把它实现成真跑命令的工具，并在 `ChatClient` 上注册，让模型能真正调用。

### 文件改动

| 文件 | 改动 |
| --- | --- |
| `ToolService.java` | 重写：真实执行 shell、捕获输出、超时保护、危险命令拦截 |
| `FakeClaudeApplication.java` | 注入 `ToolService`，加 `.defaultTools(toolService)` |
| `application.properties` | 新增 `fake-claude.shell.*` 三个配置项 |

## 二、实现要点

### 1. 跨平台执行

```java
List<String> wrapper = windows
        ? List.of("cmd.exe", "/c", command)
        : List.of("/bin/sh", "-c", command);
```

用 `ProcessBuilder`，不用 `Runtime.exec()`——后者对带空格、引号的命令解析不可靠。

### 2. 输出抽干，防止卡死

子进程输出写满管道缓冲区后会阻塞等待，主进程若先 `waitFor()` 就会互相死锁。所以开一个守护线程持续 `transferTo` 缓冲区，主进程再等待退出。

`redirectErrorStream(true)` 把 stderr 合并进 stdout，模型能同时看到报错信息。

### 3. 超时 + 杀子进程树

```java
process.descendants().forEach(ProcessHandle::destroyForcibly);
process.destroyForcibly();
```

只杀 `cmd.exe` 不够：它的子进程（如 `ping`）仍会占着管道，导致回收拖到 4 秒。加上杀后代后降到 3 秒左右。注意这类命令本身不支持，会一直卡到超时，工具描述里已写明。

### 4. 中文编码

Windows 控制台输出是 GBK，Java 按 UTF-8 解会乱码。按系统默认取 GBK，并留出 `fake-claude.shell.charset` 配置项可覆盖。

### 5. 兜底黑名单与输出截断

- 命中 `rm -rf /`、`format c:`、`shutdown`、`mkfs` 等直接拒绝（**只是防手滑，不是安全边界**）。
- 返回给模型的输出截断到 20000 字符，避免几千行日志把上下文撑爆。

### 6. 配置项

```properties
fake-claude.shell.work-dir= ${user.dir}
fake-claude.shell.timeout-seconds= 60
fake-claude.shell.charset= GBK
```

## 四、注意事项 / 后续

1. **模型必须支持 function calling** 才会触发工具；当前 `deepseek-flash` 支持。
2. **思考模式 + 工具调用有坑**：DeepSeek 在带 `tools` 的思考模式下要求把 `reasoning_content` 原样回传，否则可能返回 400。当前用的是 Spring AI 2.0.1，这部分支持不完整；若工具调用报错，需升级到 2.1.0-RC1（支持 thinking/reasoning 内容回传）或关闭思考模式。
3. 目前**没有任何权限确认机制**，模型说什么就跑什么。后续要考虑：危险命令白名单 / 执行前打印并等用户回车确认。
4. `application.properties` 里 `temperature=0.7` 在思考模式下不生效（DeepSeek 会打 WARN）。要让它生效需显式关闭思考模式。

# 追加：文件写入工具（同日晚）

模型不能只"能跑命令"，还得"能落盘"，于是又加了两个 @Tool。

## 改动

| 文件 | 改动 |
| --- | --- |
| `ToolService.java` | 新增 `writeFile(path, content)`、`appendToFile(path, content)`；新增 `baseDir` 字段与构造参数 |
| `application.properties` | 新增 `fake-claude.fs.base-dir` |

## 设计要点

1. **只能写工作目录内**：`Path.normalize()` 后校验 `startsWith(baseDir)`，挡住 `../../..` 路径穿越；额外拒绝写入 `.git` 目录。
2. **覆盖前自动备份 `.bak`**：模型可以直接改源码，这是唯一兜底。备份只有一层，连续覆盖两次旧版本就没了。
3. **父目录自动创建**：`Files.createDirectories(parent)`。
4. **UTF-8 写入**，与 shell 工具的 GBK 解码分开处理（一个是读进程输出，一个是写文件）。
5. **内容上限 200_000 字符**，防止模型一次性灌进超大文件。
6. 返回结果带：绝对路径、新建/覆盖/追加、字符数与行数、备份路径。

## 验证结果

| 用例 | 结果 |
| --- | --- |
| 新建 + 自动建多级目录 | 成功，中文内容正确 |
| 覆盖已存在文件 | 生成 `.bak`，备份内容为覆盖前原文 |
| 追加 | 追加到末尾，不备份 |
| 写 `C:\Windows\System32\evil.txt` | 拒绝，提示允许的根目录 |
| 路径穿越 `user.dir/../../..` | 归一化成 `C:\evil.txt` 后被拒绝，未落盘 |
| 空白内容 | 拒绝，提示内容为空 |

`mvn compile` 通过。

## 遗留风险

- **项目仍不是 git 仓库**，`.bak` 是唯一兜底。强烈建议尽快 `git init`。
- 工具没有确认机制，模型可静默改文件。下一步可考虑：写入前打印 diff 并等待用户回车。
